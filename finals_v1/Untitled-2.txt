Let's break down the **training phase** for your **Weather Hazard Prediction Model** in detail.

---

## ✅ **Step 1: Data Collection (Historical Data)**
### **Dataset:** 
- **Source:** Kaggle's **US Accidents Dataset (Weather Included)**  
- **Contents:**  
   - Accident Location (`latitude`, `longitude`)  
   - Weather Conditions (temperature, wind speed, precipitation, etc.)  
   - Accident Severity (target variable)  
   - Timestamp of accident  

### **Preprocessing Requirements:**
- **Location Mapping:** Convert latitude/longitude to **road segments** using **OSMnx**.  
- **Data Cleaning:** Handle missing values, outliers, and inconsistent data.  
- **Feature Selection:** Select relevant weather attributes for prediction.  

---

### 📌 **Code Example (Preprocessing)**
```python
import pandas as pd
import osmnx as ox

# Load the dataset
df = pd.read_csv('US_Accidents_Dataset.csv')

# Keep relevant columns
df = df[['Start_Lat', 'Start_Lng', 'Severity', 'Temperature(F)', 'Wind_Speed(mph)', 'Precipitation(in)', 'Visibility(mi)']]

# Remove missing values
df.dropna(inplace=True)

# Map to road segments using OSM
G = ox.graph_from_place('New York City, USA', network_type='drive')

def map_to_road(lat, lon):
    return ox.distance.nearest_nodes(G, lon, lat)

df['Road_Segment'] = df.apply(lambda x: map_to_road(x['Start_Lat'], x['Start_Lng']), axis=1)
df.to_csv('processed_accident_data.csv', index=False)
```

## ✅ **Step 2: Feature Engineering**
### **Transforming Data for ML Training:**
- **Input Features (X):**  
   - Temperature, Wind Speed, Precipitation, Visibility  
   - Road Segment ID (encoded as categorical or numeric)  
   - Time Features (day, month, season)  

- **Target Variable (y):**  
   - Accident Severity (`1 to 4`)  

### **New Features to Add:**  
- **Time of Day:** (Morning, Afternoon, Evening)  
- **Day of Week:** (Weekday/Weekend)  
- **Weather Severity Index:** Composite score based on weather conditions.  

---

### 📌 **Code Example (Feature Engineering)**
```python
# Adding time-based features
df['Time_of_Day'] = pd.to_datetime(df['Timestamp']).dt.hour
df['Day_of_Week'] = pd.to_datetime(df['Timestamp']).dt.weekday

# Encode categorical features
df = pd.get_dummies(df, columns=['Time_of_Day', 'Day_of_Week'])

# Normalize numeric features
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
scaled_features = scaler.fit_transform(df[['Temperature(F)', 'Wind_Speed(mph)', 'Precipitation(in)', 'Visibility(mi)']])
df[['Temperature(F)', 'Wind_Speed(mph)', 'Precipitation(in)', 'Visibility(mi)']] = scaled_features

# Export cleaned data
df.to_csv('final_training_data.csv', index=False)
```

---

## ✅ **Step 3: Data Splitting (Training and Testing Sets)**
- **Train-Test Split:** 80% Training, 20% Testing  
- **Stratified Splitting:** Since severity is categorical, use stratification.  

### 📌 **Code Example (Splitting)**
```python
from sklearn.model_selection import train_test_split

# Separate features and target
X = df.drop(columns=['Severity'])
y = df['Severity']

# Split the data
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)
```

---

## ✅ **Step 4: Model Selection and Training**
### **Choosing the Model:**
Since the task involves predicting accident severity (ordinal data with 4 severity levels), it’s a **classification problem**.  
- **Models to Consider:**  
   - Random Forest (baseline)  
   - Gradient Boosting (XGBoost, LightGBM)  
   - Neural Network (for later experimentation)  

### **Training a Random Forest Model:**
```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, classification_report

# Initialize and train the model
model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_train, y_train)

# Predictions
y_pred = model.predict(X_test)

# Model Evaluation
print("Accuracy:", accuracy_score(y_test, y_pred))
print(classification_report(y_test, y_pred))
```

---

## ✅ **Step 5: Model Evaluation and Tuning**
### **Metrics to Evaluate:**
- **Accuracy:** Overall correctness of the model.  
- **Confusion Matrix:** Class-wise prediction breakdown.  
- **F1-Score & Recall:** Important for imbalanced datasets.  

### **Hyperparameter Tuning (Using Grid Search):**
```python
from sklearn.model_selection import GridSearchCV

param_grid = {
    'n_estimators': [50, 100, 150],
    'max_depth': [10, 20, None]
}

# Grid search
grid_search = GridSearchCV(RandomForestClassifier(random_state=42), param_grid, cv=5, scoring='accuracy')
grid_search.fit(X_train, y_train)

# Best model
print("Best parameters:", grid_search.best_params_)
best_model = grid_search.best_estimator_
```

### **Key Issues and Areas for Improvement:**

1. **Data Integrity and Feature Handling:**
   - **Imbalanced Features:** 
     - The code lacks explicit handling of imbalanced datasets. Given the severity classification task, using techniques like `SMOTE` could help balance the dataset.
   - **Feature Engineering:**
     - The `Visibility(mi)` and `Precipitation(in)` values are heavily skewed in the US Accidents Dataset. Consider log-scaling or outlier clipping.
   - **Road Segment Mapping Issue:**
     - The call to `ox.distance.nearest_nodes(G, row['Start_Lng'], row['Start_Lat'])` may be slow and problematic for large datasets. Consider pre-caching node mappings or using vectorized operations instead.

---

2. **Model Architecture:**
   - **Activation Function:**
     - `ReLU` is prone to dying units. Consider experimenting with `LeakyReLU` or `GELU`.
   - **Output Layer and Classes:**
     - The output layer uses 4 units for predicting severity but doesn't confirm if the dataset has only 4 classes. Ensure proper alignment between the number of classes and the dataset's labels.
   - **Overfitting:**
     - The hidden size of 128 might be excessive for this dataset, leading to overfitting. Try reducing it or using regularization techniques like batch normalization.

---

3. **Training Process and Metrics:**
   - **Evaluation Metric:**
     - The model relies only on accuracy, which is not ideal for imbalanced datasets. Consider using `F1-score`, `Precision`, and `Recall`.
   - **Learning Rate and Early Stopping:**
     - No learning rate scheduling or early stopping is implemented. This could lead to inefficient training.
   - **Loss Convergence Monitoring:**
     - Printing average loss per epoch is good, but visualizing it using `matplotlib` could be more insightful.

---

4. **Performance Bottlenecks and Scalability:**
   - **Device Management:**
     - While the model checks for CUDA, there's no explicit device transfer for data (`features` and `labels`) during evaluation and prediction.
   - **Batch Size:**
     - Batch size of 32 might be too small for weather datasets. Try increasing it to 64 or 128 for faster convergence.

---

### **Recommendations for Improvement:**
1. **Data Handling:**
   - Add SMOTE for class balancing.
   - Cache or vectorize the `osmnx` calls to speed up geospatial queries.
2. **Model:**
   - Reduce hidden layer size or experiment with batch normalization.
   - Use `LeakyReLU` instead of `ReLU`.
3. **Training:**
   - Implement early stopping and learning rate scheduling.
   - Use `F1-score` and confusion matrix for better performance evaluation.
4. **Performance:**
   - Ensure both data and model are on the same device (`.to(self.device)`).
